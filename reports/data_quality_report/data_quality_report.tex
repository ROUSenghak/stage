\section{Objective and Scope}

This report documents the quality of the BOAMP corpus used to construct the
renewal proxy and the survival modeling dataset, and whether the dataset is
reliable enough to support Phase 2. The scope is the BOAMP-only pipeline for
digital-sector public procurement notices in Pays de la Loire over 2015--2024.
The official modeling population is the set of eligible \texttt{APPEL\_OFFRE}
contracts retained in \texttt{data/processed/boamp\_phase2\_survival.csv}. In
this report, \texttt{event = 1} denotes a \emph{proxy renewal event} found by the
linking algorithm; \texttt{event = 0} denotes right-censoring or no observed link
under the rule before the study end date. It does not prove that no renewal
occurred. The report covers: the raw corpus and final population, missing-value
and cleaning decisions, the dominant data-quality issues, duration reliability,
buyer identification and SIREN enrichment, the exact construction of the
\texttt{event} variable, its validation and robustness, and the limitations that
carry into survival analysis.

\section{Key Data Quality Issues}

The dominant data quality problems are structural rather than cosmetic. Buyer
identity was initially weak because the eligible cohort had no SIRET-anchored
\texttt{buyer\_key}; most grouping relied on normalized buyer names. SIREN
enrichment (completed 2026-06-24 via the API Recherche d'Entreprises) has
partially resolved this: 660 of the 1{,}100 eligible rows now carry a
HIGH-confidence SIREN-enriched buyer identity in
\texttt{boamp\_phase2\_survival\_siren\_enriched.csv}; 440 remain on the
name-based key (see Section~\ref{sec:siren-enrichment}). Residual name-based
fragmentation remains possible for the unresolved cases. CPV coverage is high
but not perfect, and generic CPV values reduce matching precision. Contract
amount is sparse on source notices, so it cannot support renewal linking. BOAMP
also has no explicit renewal label, which means the linking output is
necessarily an inferred event proxy.

\section{Buyer Identification and SIREN/SIRET Enrichment}
\label{sec:siren-enrichment}

\subsection{Motivation: buyer fragmentation}

The baseline pipeline builds a canonical buyer key using a SIRET-first rule: when
a valid 14-digit SIRET is present in the BOAMP record, the key is
\texttt{SIRET:\{14-digit\}}; otherwise it falls back to a normalized name key
\texttt{NAME:\{normalized\_name\}} after stripping accents, punctuation, and
legal-form suffixes. In the cleaned corpus, approximately 95\% of rows carry a
name-based key. Because the same public buyer can appear under slightly different
spellings across procurements (\emph{e.g.}\ ``Ville de Nantes'' vs.\ ``Nantes
Métropole''), name-based keys fragment what is in reality a single buyer into
multiple groups. Fragmented groups reduce the pool of candidate renewals
available to the linker and can produce false negatives in the event variable.

\subsection{Data source and tool}

Enrichment uses the \emph{API Recherche d'Entreprises}
(\url{https://recherche-entreprises.api.gouv.fr}), the official open-data search
interface for the French SIRENE register. It is publicly accessible, requires no
authentication, and covers all legal entities registered in France, including
public bodies (\emph{communes}, \emph{départements}, \emph{établissements
publics}, hospitals, \emph{intercommunalités}). The API returns up to ten
candidates per query with a declared rate limit of 7 requests per second; the
pipeline uses a conservative limit of 5 requests per second with local caching to
avoid redundant calls on re-runs.

\subsection{Why SIREN, not SIRET}

SIRET (14 digits) identifies a specific establishment of a legal entity. SIREN
(9 digits) identifies the legal entity itself. For buyer grouping, SIREN is more
appropriate: a single public buyer (\emph{e.g.}\ a \emph{département}) can have
multiple establishments with different SIRETs but a single SIREN. Using SIREN as
the enriched key prefix (\texttt{SIREN:\{9-digit\}}) makes the source and
grouping level unambiguous and distinguishes enriched keys from BOAMP-sourced
keys (which retain the \texttt{SIRET:} prefix).

\subsection{Matching method and confidence levels}

For each unique buyer name, the pipeline:
\begin{enumerate}[noitemsep]
  \item Detects the likely entity type from the name (commune, SDIS, CHU,
    région, EPCI, etc.) to select the appropriate \emph{nature juridique} API
    filter and query formulation.
  \item Queries the API with the normalized buyer name, filtered by department
    code when available.
  \item Scores every returned candidate using a token-sort string similarity
    (rapidfuzz) on normalized names, with a small bonus for token overlap and a
    department-match check.
  \item Classifies the best candidate into one of four confidence levels:
\end{enumerate}

\begin{table}[H]
\centering
\small
\begin{tabularx}{\linewidth}{@{}L{2.4cm}L{4.4cm}Y@{}}
\toprule
\textbf{Level} & \textbf{Score threshold} & \textbf{Interpretation} \\
\midrule
HIGH   & $\geq 85$, or $\geq 75$ with single candidate or margin $\geq 10$ &
         Strong match; used automatically for \texttt{buyer\_key\_enriched} \\
MEDIUM & $\geq 70$ (not HIGH) & Plausible but ambiguous; retained for manual review only \\
LOW    & $\geq 55$ (not MEDIUM) & Weak or generic match; not used automatically \\
NO\_MATCH & $< 55$ or no candidates & No reliable candidate found \\
\bottomrule
\end{tabularx}
\caption{Confidence classification for SIREN enrichment.}
\label{tab:siren-confidence}
\end{table}

\subsection{New buyer key}

A new column \texttt{buyer\_key\_enriched} is defined with a simple rule: use
\texttt{SIREN:\{siren\}} when the match is HIGH confidence and the SIREN is valid;
otherwise keep the original \texttt{buyer\_key}. MEDIUM, LOW, and NO\_MATCH rows
are therefore unchanged. The original \texttt{buyer\_key} is preserved in
\texttt{buyer\_key\_original}. Confidence levels MEDIUM and LOW are surfaced in
\nolinkurl{buyer_siren_enrichment/outputs/ambiguous_buyer_matches_for_review.csv}
for optional manual validation but are never applied automatically.

\subsection{Coverage and effect on renewal linking}

Of the 1{,}100 eligible contracts, 660 carry a \texttt{SIREN:} key and 440 a
\texttt{NAME:} key after enrichment; 275 of 525 unique buyers (52.4\%) matched
with HIGH confidence. Relative to the name-only baseline, the SIREN-based merges
added 8 renewal events (697 $\to$ 705), lifting the eligible linking rate from
63.4\% to 64.1\%. An \textbf{auxiliary Jaccard-based comparison} was also run
separately from the official Sentence-Transformer phase-2 pipeline, using
\texttt{buyer\_key\_enriched} for grouping (window $\pm 12$ months, Jaccard
threshold 0.20, weighting 0.7 text + 0.3 time). It produces two auxiliary files,
\nolinkurl{boamp_full_survival.csv} (name-based baseline, 1{,}933 rows) and
\nolinkurl{boamp_full_survival_enriched.csv} (SIREN-enriched, 1{,}933 rows) in
\nolinkurl{boamp_renewal_linking_siren_enriched/outputs/}; these are
\textbf{legacy comparison artifacts}, not the current-stage survival dataset.
Numerical comparison results are saved in
\nolinkurl{buyer_siren_enrichment/outputs/baseline_vs_siren_enriched_linking_comparison.csv}.

\subsection{Limitations}

\begin{itemize}[noitemsep]
  \item \textbf{API results are not ground truth.} The SIRENE register records
    the entity as legally registered, not necessarily under the name used in
    procurement. Fuzzy matching can produce false positives, particularly for
    common generic names.
  \item \textbf{MEDIUM and LOW matches are not applied automatically.} They are
    kept in the review file for optional human validation.
  \item \textbf{HIGH-confidence mistakes remain possible.} A score $\geq 85$ does
    not guarantee a correct match; it reflects strong textual similarity under a
    specific normalization scheme. Rare false positives at HIGH confidence would
    introduce a small number of incorrect group merges.
  \item \textbf{NO\_MATCH buyers are unresolved.} Buyers with acronyms, internal
    codes, or abbreviated names (\emph{e.g.}\ ``CNIEG'', ``SAELSI'', ``DIR
    Ouest'') often fail to match and remain name-keyed. Their renewal groups are
    unchanged relative to the baseline.
  \item \textbf{The SIREN enrichment annotation does not recompute the event
    variable.} The official phase-2 dataset (\nolinkurl{boamp_phase2_survival.csv},
    705 events) incorporates SIREN-based buyer key merges into its
    \texttt{buyer\_key} column (660 \texttt{SIREN:} keys, 440 \texttt{NAME:}
    keys). The file \nolinkurl{boamp_phase2_survival_siren_enriched.csv} extends it
    with four annotation columns (\texttt{buyer\_key\_enriched},
    \texttt{enriched\_siren}, \texttt{enrichment\_confidence},
    \texttt{enrichment\_score}) added by left-join; these record enrichment
    metadata but do not change the event or survival-time columns.
\end{itemize}

\textbf{Scientific framing.} SIREN enrichment is a buyer-resolution improvement,
not a new ground truth. It is expected to reduce false negatives arising from
buyer fragmentation and to improve the precision of renewal-group boundaries, but
it cannot compensate for the fundamental limitation that \texttt{event} remains a
proxy.

\section{Construction of the \texttt{event} Variable}

\subsection{Exact definition}

\texttt{event = 1} is assigned when the linking algorithm finds a later BOAMP
\texttt{APPEL\_OFFRE} notice from the same buyer within a window of [6, 72] months
around the source contract's expected end date, passing a hard
\texttt{text\_similarity} $\geq 0.20$ filter, and achieving the highest composite
score among all candidates considered. The renewal variable is constructed by
matching later notices from the same \texttt{buyer\_key} using text, CPV, and
timing; BOAMP provides no explicit renewal ID.

\subsection{Scoring formula}

For source contract $i$ and candidate $j$ the composite score is:
\[
  S(i,j) = 0.40\,s_{\mathrm{text}} + 0.25\,s_{\mathrm{cpv}}
          + 0.20\,s_{\mathrm{temp}} + 0.15\,s_{\mathrm{buyer}}
\]
When CPV is missing for either notice, the CPV weight is redistributed
proportionally: $S = (0.40\,s_{\mathrm{text}} + 0.20\,s_{\mathrm{temp}} +
0.15\,s_{\mathrm{buyer}})\,/\,0.75$.

\subsection{Hard threshold and justification}

The \textbf{only hard acceptance threshold} in the baseline model is
\texttt{text\_similarity} $\geq 0.20$; no composite floor is applied. The hard
filter is placed on text similarity because semantic similarity of the contract
description is the most reliable single discriminator between a genuine renewal
and an unrelated later notice from the same buyer. The observed minimum composite
score for accepted links is approximately $0.37$, arising from the weighting
formula applied to pairs that pass the text filter. Two post-hoc confidence tiers
are defined for sensitivity analysis:
\begin{itemize}[nosep]
  \item Medium/high confidence: composite $\geq 0.50$ --- 497 of 705 events (70.5\%);
  \item Strict high-confidence: composite $\geq 0.70$ \emph{and} score margin
        $\geq 0.05$, multi-candidate links only --- 100 events (14.2\%).
\end{itemize}

\subsection{Interpretation of \texttt{event = 0}}

\texttt{event = 0} is right-censored: no successor was detected under the rule
before the 2024-12-31 study end. Right-censoring does \emph{not} mean the contract
was not renewed; it means no identifiable BOAMP successor was found under the
current chaining rule (for example, the renewal may fall after study end, may be
procured through a channel that does not generate a new BOAMP notice, or may use a
buyer name that fragments away from the source key). The variable is therefore a
\textbf{proxy chaining result}, not a legally certified renewal and not a confirmed
absence of renewal.

\subsection{Uncertain cases and score margins}

The median composite score of the 705 accepted links is 0.555 (IQR 0.489--0.653).
Of the 572 multi-candidate links, 265 (46.3\%) have a score margin below 0.05 ---
the algorithm selected a winner but an alternative was nearly equally plausible.
Removing all uncertain links (composite $< 0.50$ or margin $< 0.05$) reduces the
analysis to 767 contracts and 372 events (48.5\%), shifts the KM median to 54.8
months, and lowers the Cox concordance from 0.6541 to 0.601. The drop in
concordance confirms that the uncertain links carry positive discriminative signal
and do not appear to introduce dominant systematic bias.

\subsection{Event/censoring bias comparison}

Covariate balance between linked (event$=1$) and censored (event$=0$) contracts is
good on all survival-model predictors: the standardised mean difference (SMD) is
0.128 for declared duration, $-0.029$ for start year, and $-0.019$ for the
imputation flag --- all well below the conventional 0.20 threshold for substantial
imbalance. The largest observed imbalance is amount non-missing ($\Delta = -0.099$):
censored contracts are more likely to carry a reported amount, possibly because
high-value contracts are renegotiated through channels that do not produce a new
BOAMP notice. This does not affect the survival model (amount is not a covariate).

Event rate by cohort year is broadly stable at 56--75\% for contracts starting in
2015--2022. The 2023 cohort shows only 4 linked events out of 12 eligible (33.3\%),
but the sample is too small to interpret as a trend; the short observation window
(less than 24 months to study end) is the more likely explanation. The dominant
source of bias remains \textbf{structural right-censoring} of the 2022--2024
cohort, whose expected renewal windows fall after the 2024-12-31 study end --- a
study-design constraint, not a measurement error in the linking rule.

\medskip
\noindent In summary, the 64.1\% linking rate should be read as a \textbf{chaining
result}: the proportion of eligible contracts for which the algorithm identified a
plausible BOAMP successor under the current rule. It is \emph{not} a measurement of
the true renewal rate, because false positives and false negatives are both
possible and no empirical precision estimate is yet available. The sensitivity
analysis demonstrates, however, that the qualitative conclusions of the survival
model are stable across all seven threshold scenarios tested. The variable is fit
for purpose as a prioritisation signal, provided its proxy nature is communicated
wherever the model output is used.

\section{Limitations and Impact on Survival Analysis}

Selection bias remains possible because contracts with no temporal partner cannot
be linked even if a real-world renewal occurred outside the observable window.
Buyer fragmentation can create false negatives, while generic or repetitive
contract descriptions can create false positives. Missing or generic CPV reduces
auditability. Contracts from late 2023 face compressed observation windows, and
2024 contracts are structurally excluded from the eligible denominator because
their expected renewal window falls after study end. Manual validation is still
required to estimate the precision of the proxy renewal event.

\section{Conclusion}

The BOAMP dataset satisfies the internship guide's minimum data-quality
requirement for Phase 1 because it provides a documented corpus, explicit cleaning
rules, missingness information, a transparent linking rate, and a survival-ready
population of 1{,}100 eligible contracts with either observed or censored duration.
The main limitation is conceptual rather than technical: \texttt{event} remains a
proxy renewal event, not legal ground truth. The 64.1\% figure is a chaining/linking
rate, not a measured true renewal rate; SIREN enrichment is a buyer-resolution
improvement, not ground truth; and manual validation has not yet been executed, so
precision and recall of the linking step remain unknown. Executing the 150-row
manual review is the priority next step to put an empirical bound on event quality.
